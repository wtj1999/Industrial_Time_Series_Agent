# NG 深度分析

点击结果表每一行右侧的“深度分析”，输入框会显示“针对当前{不良名称}进行深度分析”。提交后，LLM使用真实参数中文释义推荐一个目标字段及每个上游工序最多三个特征。用户可以改选目标、勾选特征、搜索其他数值字段，第二次提交后才查询参数值。新结果默认进入目标画像，按五步流程浏览；旧结果仍支持原有工序/字段图表。

## 五步分析流程

### 自动清洗后的统一分析

取数仍先按工序规则选目标时点的最新记录，再剔除其他缺陷或质量未知的产品。这些产品不进入ADS追溯、上游取数、清洗统计或可视化。当前缺陷NG和确认OK的产品标签及数量保留；一个字段无效只剔除此字段值，不回退到更早记录，也不影响其他字段。多个上游码中部分参数无效时保留其余有效值。

规则文件为各工厂字典目录下的`measurement_quality_rules.json`。当前金寨三期版本为`2026-11-18.3`，只启用基础校验和MAD自动剔除，不要求用户配置单位。空值归入缺失；非数值、非有限值和MAD越界值归入算法剔除。0、负数、超产品合格规格的有效值不全局删除。生产库原始记录保持不变。

```json
{
  "version": "2026-11-18.3",
  "min_records": 50,
  "modified_z_limit": 5.0,
  "fields": []
}
```

在每个工序、字段内，MAD按**租户＋产线＋NG/OK**分别计算，不按设备、工单拆组。各组按独立源记录估计中位数和MAD，修正Z为`0.6745 × (值－中位数) / MAD`，绝对值超过5时剔除此字段值；上下限为`中位数 ± 5 × MAD / 0.6745`，边界上的值保留。独立记录少于50条、MAD为0、疑似多峰或数值尺度不稳定时不强行检测，账本说明原因。旧规则中的更细`group_by`不会重新拆分设备和工单；NG/OK作为内部标签分组自动加入。

同一源记录在同组关联多个目标产品，只贡献一次MAD样本；同时关联NG和OK时，在两组各贡献一次，分别接受本组上下限判定。因此账本原始记录数是NG/OK组内独立源记录数之和。图表、目标画像和候选因素统一使用剔除后的值，不再提供包含/排除对照切换，也不为切换重复计算模型。

清洗账本展示八列：**工序 / 字段、原始记录、缺失、算法剔除、算法判定上下限、剩余有效、受影响NG/OK、核查**。上下限按组列出；`原始记录 = 缺失 + 算法剔除 + 剩余有效`。“受影响NG/OK”表示此字段存在缺失或被剔除数值的目标产品数，不表示删除这些产品或清空其余字段。当前特征有效覆盖产品数在对应图表中另列。核查记录保留源编码、所属NG/OK组、原值、用于分析值、原因和规则版本。

模型按目标产品构建，每个目标码一行；不同产品共享同一上游码时各自保留，不进行物料重叠剔除。MAD阈值只由训练记录估计，训练数据按已知NG/OK组应用阈值；验证集不读取真实标签选择阈值，仅在同时超出该租户、产线训练NG和OK两组范围时剔除，任一训练组不足时保留。阈值仍按组内源记录估计，模型行则按目标产品保留。该做法避免验证标签参与清洗，模型使用的数值集合可能与全量快照的回顾性图表略有差别。现场验证记录使用`quality_view=automatic_cleaned`。

审计通过`POST /api/bi/ng/deep/quality/audit`分页读取，绑定分析ID、认证用户、工厂及会话。分析档案保存规则快照，便于复核；原有档案保留旧清洗口径，需重新提交分析才能应用新规则。内部仍支持经工程师确认的逐字段物理量程或来源规则，但当前`fields`为空，不猜测物理量程或自动纠正单位。

1. **目标画像**：先读取目标宽表的目标数值、真实`device_name`、`shift`、`shift_date`和工单，展示总体、设备、白夜班、设备×班次的NG/OK分布。直方图与NG占比图合并为区间气泡图：横轴为目标值区间，纵轴为该区间NG/(NG+OK)，气泡面积表示有效目标产品数，悬浮及区间选择显示NG、OK和覆盖数量；另保留竖向箱线图，每次一张图，箱线图不画离群点。气泡直接按既有分箱的NG/OK计数转换，不从分位数估造数据，也不增加数据库取数；历史结果的原分箱边界同样保留。设备、班次与组合维度可选具体分组查看气泡，汇总表保持各组总体NG占比及有效目标数，可点击分组切换图表，超过6组分页。气泡仅包含有效目标值，分组总体占比仍包含目标值缺失或被剔除但质量标签明确的产品。设备跨租户、产线分别统计。班次直接读取`shift`，不按结束时间推断；未知班次单列。每组给出NG/OK数量、有效目标数和中位数，并生成描述性定位线索。没有规格限时不计算Cpk或推断超标阈值。
2. **候选因素**：以当前NG标签为主要响应，目标测量值作为辅助质量响应。每个目标产品的全部已关联上游码用中位数和极差形成分析特征，原始图表继续保留全部关联值。比较NG/OK的位置、极差分布KS距离。候选表直接展示Spearman系数及有效配对产品数：每个目标产品的上游有效参数先取中位数，再与该产品的有效目标值配对，每个产品只贡献一对，多码不展开成多条相关样本。另列“区间NG占比/覆盖产品”，按三行显示探索区间：`[下限, 上限]`、`NG占比 xx%`、`覆盖产品 xx`，表格前后的通用筛选、分界与共享物料说明文字移除；无可用区间显示“—”。原“与目标数值的联系及探索性高NG区间”折叠区移除。区间提升倍数的后台口径仍为区间NG占比除以当前字段有效覆盖产品的NG占比，用于探索描述，不代表因果风险倍数。未发现差异、无变化、有效产品不足、共享物料独立编码不足等情况明确标注。无跨产品重复上游码时给Mann–Whitney位置检验及BH校正；共享物料不输出把重复电芯当独立测量的p值。候选表移除独立的“指标解释”列。在每行“位置/极差效应”与“可比条件内占比差”的数值处，鼠标悬浮、键盘聚焦或点击会弹出该指标的解释：前者说明参数分布和多码极差分布的最大累计占比差，后者按真实分界值解释高值一侧的NG占比更高、更低或相同；无可比条件、样本不足、覆盖不足及来源有限时说明具体限制。气泡挂载到表格滚动容器外，按视口调整位置，移开、失焦、按Esc、点击外部或滚动时收起。正负方向、零差异和无法计算分别展示，不用通用候选状态文案代替指标含义。固定阈值仅为筛选规则，不保证因果关系。
3. **多因素与验证集评估**：按目标结束时间先后以7:3初分训练集和验证集，同一时点不会拆到两个集合，因此边界有并列时实际初分数量可能略有偏差。每个目标产品一行，不同目标产品共享上游码时分别保留；多个上游码仍以中位数及极差形成该产品的模型特征。清洗阈值和最多12个字段的筛选均只使用训练数据，选因以参数中位数/极差的NG/OK分布KS距离排序。字段须覆盖至少40个且至少50%的训练产品并有变化，不再以独立物料编码数筛除模型因素。当前模型仅使用入选字段均有有效值的完整产品，页面分别列初分、最终入模和字段缺失未入模数量。分别训练生产上下文CatBoost基线和加入上游因素的模型，两者均固定1000轮，关闭最佳轮数裁剪，不传入eval_set或早停参数。两模型在相同验证产品上计算ROC-AUC和AP，CatBoost原生SHAP解释验证集预测，证据报告Top 3同样使用验证集贡献。验证集不参与训练、选因、阈值估计或轮数选择。目标数值、NG判定、产品码不作为输入。训练集和验证集各需至少10个NG和10个OK；不足时明确返回原因，不重新拆分或以训练集代替评估。完整模型样本上限50,000，超过时暂停建模，不截取图表。跨日期验证按训练集与验证集的班次日期是否分离判断。结果标记为`evaluation_set=validation`、`validation=chronological_70_30`，实际轮数见`training.baseline/augmented`；`test_products=0`仅保留接口兼容，新结果不展示测试集。历史结果保留原评估口径，重新提交分析才使用新划分。
4. **证据报告**：整理描述性差异、条件内比较、跨日期方向复现、模型证据、推荐阶段工艺假设、替代解释及对照验证动作。推荐理由仅在目标未改选时沿用，始终标注待工程师核实；未推荐字段不编造工艺机制。所有因素保持`causal_status=unconfirmed`。模型失败会保留画像和筛选，取消请求则终止后续工作。
5. **现场验证**：工程师记录假设、调整动作、保持条件、前后NG/总数、是否独立批次复验及结论。保存为追加式不可覆盖记录；显示前后比例及百分点差，但不由单纯前后变化自动确认因果。完成类结论要求前后数量和说明，NG不能大于总数。记录按工厂、认证用户、会话和分析ID隔离，字段必须属于该次分析。记录及对应分析摘要保存在独立的`*.rca.sqlite3`中，不随24小时字段确认过期而删除。

设备和班次图的NG占比、因素区间占比均仅针对当前缺陷NG与确认OK的比较样本，不是全产线不良率。材料关联、分容工步10、化成最大数值工步、其他工序最新记录等取数规则不因本流程改变。

接口新增`POST /api/bi/ng/deep/validation/list`与`POST /api/bi/ng/deep/validation/record`；沿用现有认证。分析结果包含`target_profile`、`root_cause`及持久化后的`analysis_id`。原流接口会实时发出画像、筛选、训练、验证、报告阶段的进度。

## 区间气泡图与字段切换

正负极合浆、涂布、辊压（C1101、C1103、C1201、C1202、C1301、C1302）为共享物料分析，只显示区间气泡图。其他工序同时提供气泡图和箱线图，气泡图为第一个选项，箱线图为第二个；两种图互斥显示。工序按钮下只显示本工序已选字段的按钮，点击字段时回到气泡图。

气泡图横轴按当前字段全部有效参数的最小值、最大值划分最多10个等宽区间；不同值不足10个时相应减少区间，全为相同值时保留一个闭区间。每个圆代表一个区间。纵轴为区间内的`去重NG产品数 / (去重NG产品数 + 去重OK产品数)`，面积为该区间覆盖的不同目标产品数；NG仍指当前缺陷，其他缺陷或质量未知的产品不进入分母，所以该比例不是全产线不良率。空区间没有圆，比例返回null，不误表示为0%。可点击圆或用区间下拉框查看准确边界、NG/OK数量、覆盖产品数、上游码数和实际测量记录数。

共享物料和多个卷绕码均采用区间内产品去重：同一个电芯的多个上游码或多条关联落在同一区间时，该电芯只计一次；落在不同区间时，每个区间分别覆盖该电芯。不同区间可能共享电芯，因此不能将所有气泡的覆盖数或NG数直接相加。后端独立返回全字段去重覆盖产品数`bubble.covered_products`，以及每个区间的关联参数数、不同上游码数、不同实际测量记录数；生产原始编码不返回前端。

箱线图继续使用全部有效的电芯—上游码参数分布；不绘制离群散点，显示范围采用两组须端点，防止隐藏的极端离群值压扁箱体。离群值仍参与分位数和统计计算。共享物料页面隐藏箱线图及关联次数加权的中位数，不把这些统计当作主要分析视图。旧结果没有分箱数据时提示重新提交分析，不从分位数伪造气泡图。

摘要的“ADS追溯参数条数（当前工序）”使用当前字段有效的实际上游记录数（`parameter_record_count`），中位数使用同一批记录（`parameter_record_median`）。每个NG/OK组内按租户、上游码、所选记录时间及记录标识去重；相同值的不同上游码分别计数，空值不计数，同一上游记录可分别进入NG和OK组。该摘要不按目标电芯关联次数加权，和箱线图的关联样本口径分开。“覆盖目标产品码”仍为具有至少一个有效参数的目标产品数/该组目标产品总数。原`ads_products`仅表示找到上游编码关联的目标产品数，保留接口兼容但不用于摘要。旧结果缺少新字段时显示“—”，需重新分析。

相关检查：`python -m pytest bi_app/ng/test_visualization.py`执行区间边界、同区间去重、跨区间多重归属、共享物料记录去重、空区间和端点测试；`npm run test:ng-deep`验证服务端渲染，`npm run test:ng-deep-ui`在本机独立无界面Chrome中验证桌面/手机/320px宽度、工序和字段切换、默认气泡图、共享工序限制、箱线图没有圆点以及区间选择。图表不会独立证明根因。

## 字典与映射

金寨三期的字段字典直接来自各参数宽表 DDL 元数据，不再读取 `mes.produce_param`，也不再进行 MES 参数码与宽表列名匹配。

统一字典为 `data/jinzhai-phase-3/numeric_field_catalog.json`，按用户确认的分析范围保存 33 张工序参数宽表、1,758 个数值测量字段：

- `table_schema`、`table_name`、`table_comment`：数据库、表名及表中文描述；表描述读取 `information_schema.tables.TABLE_COMMENT`。
- `columns`：仅保存数值测量特征，每列包含 `column_name`、`column_comment`、`data_type`；中文释义和类型直接读取 `information_schema.columns.COLUMN_COMMENT/DATA_TYPE`，保留 DDL 原始内容及单位。
- `technics_processes`：该宽表对应的工序码、工序名称及顺序；仍从 `dim.dim_qual_defect_ni` 和实际宽表记录核验。工序路由取表内最新日期附近的记录，避免混入已修正的历史错误工序码。
- `context_columns`：实际存在的关联、时间、分组与筛选列名，单独记录可用性，供参数化 SQL 使用；不作为模型的数值特征候选。
- `partition`、`sort_time_field`、`sort_time_source`：逐表读取 `SHOW CREATE TABLE`，从 `PARTITION BY RANGE` 的时间列确定排序时间。已核实本厂35张表均为 `PARTITION BY RANGE(end_time)`，每张表保存 `sort_time_field: "end_time"`，运行时读取此配置。
- `date_filter_field`：与排序字段分开保存。34张可分析工序表都具有DATE类型的 `shift_date`，保存 `date_filter_field: "shift_date"`；排废内阻补偿表缺少该字段，保存null并继续禁用取数映射。
- `record_selection`：分容为 `fixed_step_latest`，固定 `technics_step_code="10"`；化成为 `last_numeric_step_latest`，每个产品先取数值最大的工步，再取该工步的最新记录；其他表为 `latest`。规则在目标和上游查询中共同使用。
- `revision`、`warnings`、`unmapped_processes`：字典版本、不可用表和未映射工序的说明。

当前34张表全部有工序取数映射。2026-11-20补入C1502热压对应的`dwd_qual_hot_press_pim`，保存33个DDL数值字段；314Ah和588Ah均经ADS样本反查验证关联字段为`winding_slit_code`。该表不符合`*_param_pim`命名，已加入金寨三期明确的额外工序表清单，后续刷新会同时读取其DDL和字段元数据。`dwd_qual_scrap_inter_resis_comp_param_pim`经用户确认不是工序宽表，已从分析字典中移除；`dwd_qual_pos_ceramic_mixing_param_pim`及C1102正极陶瓷合浆因无法串连也已移除，包括数值候选字段。排除规则在刷新时生效，不会重新加回。本次字典的所有数值特征列均有DDL注释。当前完整表名、工序及两路线关联字段见`data/jinzhai-phase-3/numeric_field_catalog_tables.md`。尚未匹配的工序为C1501预热、C1505极耳预焊、C2000预充、C3400 OCV5；热压关联核验记录见`data/jinzhai-phase-3/hot_press_linkage_2026-11-20.json`。

数值特征根据 schema 类型筛选，支持 decimal、float、double、整数等；排除字符串、主键、编码、数量汇总、质量分组及状态/判定标志。没有 DDL 注释的数值列会保留原列名并给出提示，不编造中文释义。

LLM 输入同时包含工序、表名、表中文描述、列名、列中文注释、数值类型及取数规则，只能返回字典中的字段 ID，不能修改时间或工步规则。字段发现不依赖生产日期或参数采集量，宽表中存在的数值特征不再因 MES 缺少记录或参数码命名不一致而遗漏。旧的 `param_dictionary.json` 和 `process_mapping.json` 已删除，工序映射合并到新字典。

## 工序产品编码与ADS路线映射

2026-11-17首次对35张候选表核验，之后按用户确认剔除两张，当前分析字典为33张：每个租户、产线分别抽取表内最新时间前7天的至多100个不同`product_code`，再从两条路线近期已经生成追溯的电芯反查较早工序，避免把“最新上游产品尚未进入一次氦检”误判为没有编码关联。反查每个追溯日期最多100个电芯。本次314Ah样本800个电芯、1600行，588Ah样本148个电芯、592行。核验只执行SELECT和元数据读取，不改数据库。

逐表映射存入同一个`numeric_field_catalog.json`：

- 顶层`code_trace_routes`保存分路线的真实表名、中文注释、可用编码列及其DDL注释；`code_trace_audit`记录核验来源和样本范围。
- 顶层`code_trace_policy.line_bindings`保存实测的租户、目标产线与路线绑定：`11300001 / 金寨三期314Ah → 314ah`，`11300001 / 金寨三期588AH → 588ah`。无法确定路线时不能把两张追溯表合并使用。
- 每张表的`code_linkage.resolved_mapping[route].product_code_field`是该工序`product_code`应对应的ADS列；同时保存其他命中列、选择依据、匹配数和状态。`verified_on_sample`是样本验证，`limited_samples`表示只有1至2个不同编码支持，`user_confirmed`为用户明确确认（高温静置1的两路线均对应`cell_code`），`no_match`不猜测映射。`routes`保留近期宽表抽样的原始统计，`completed_cell_backcheck`保留已生成追溯电芯的反查统计，两套样本可能重叠，数量不能直接相加。用户确认不会被重新抽样或DDL刷新覆盖，也不会伪造原始匹配数。
- 多个追溯字段共享部分编码时，先比较反查覆盖的不同工序产品码数；覆盖数相同再比较该字段候选编码在工序表内的命中率，仍不能区分则标记待核验。保留这些评分供复核，不仅凭字段名或条码格式选择。

样本验证的对应关系：正负合浆、涂布、辊分分别使用同名`pos_*_code / neg_*_code`；卷绕、极耳翻折、X-ray使用`winding_slit_code`；超声焊和连接片激光焊使用`butterfly_weld_code`；包膜入壳及顶盖激光焊使用`wrap_can_insert_code`；一次氦检的当前样本、烘烤及后续工序使用`cell_code`（高温静置1由用户确认）。588Ah正负合浆的支持样本较少，已单独注明。当前33张工序表均已配置两路线的对应字段。

实际深度分析已接入ADS一对多追溯。电芯码目标按各自目标时点选择最新追溯批次，使用MAX(end_time)而非ROW_NUMBER，只保留该批次但保留批次内全部物料行。每个目标产品下，各工序的上游码分别去重；同一个上游码经多个卷绕码路径重复出现时只计一次，不把多列关系做笛卡尔积。多个不同上游码即使参数值相同，也分别保留样本。码的数量按真实追溯结果确定，不硬编码314Ah为2或588Ah为4。目标和特征使用相同码字段时直接关联，无需查询ADS。

ADS在一次氦检生成，早于一次氦检的工序目标不能要求其追溯记录也早于目标。因此，非电芯物料码目标使用最新已知编码关系；各上游数值参数依然严格按目标自己的end_time选取，禁止使用未来参数记录。电芯码目标使用不晚于目标时点的最新追溯批次。查询先取批次最大时点候选，仅对候选晚于产品自身时点的请求执行精确时点补查；两个阶段最多8路并发。

非共享工序箱线图的样本单位为“目标产品与上游码的关联”。例如一个NG电芯有4个卷绕码，对应4个有效值，4个值全部进入NG组，不求平均；NG产品数仍为1。同一物料供给多个目标产品时，各产品的关联分别计入箱线图统计，样本具有相关性，不能视作相互独立的观测。气泡图则把这些值全部用于分箱，并在各区间内按产品去重。前端分别显示覆盖产品数、缺失参数数、完全缺失产品数、部分缺失产品数和多码产品数；非共享工序另显示关联参数数。追溯未知的产品没有已知码数，计入缺失产品，但不凭2/4倍数虚构缺失参数数。部分码没有记录或数值时保留其他有效码，缺失不填零。

## 取数与关联

1. 服务端保存原查询的日期、用户确认的六类筛选和结果行，按用户、会话和工厂隔离；用户不能在深度分析接口中替换这些条件。点击分组行时再叠加该行日期、设备等维度，与原筛选取交集。
2. 从字典定位目标工序宽表后，按字典中的 `date_filter_field="shift_date"` 及用户已选条件筛选，起止班次日期均包含。例如11月15日为 `shift_date >= '2026-11-15' AND shift_date <= '2026-11-15'`。跨午夜但仍属于该班次日期的记录保留；日期筛选不再使用end_time自然日。缺少shift_date的目标表会明确报错，不自动回退到其他日期字段。
3. 数据库内使用 `ROW_NUMBER()`，按 `(tenant_id, product_code)` 执行各工序规则后只返回一条。分容先筛选工步10，再按分区时间倒序；化成只接受数值工步编码，按工步编码转BIGINT倒序、分区时间倒序，避免字符串排序把9排在19前；其他工序只按分区时间倒序。时间相同时用记录ID及已选值稳定排序。化成“最后工步”按每个产品在当前可用时间范围内的最大数值工步判断，不硬编码全表最大工步，也不假定各产品工艺路线长度一致。没有工步10的分容产品记为缺失，不回退到其他工步。
4. 上限仍为默认200,000条，但现在约束数据库按规则选取后返回的结果及服务端实际保留的上游记录，不再先下载全部历史工步再按原始历史行数报超限。前端显示返回行数及按规则合并的原始记录数，不使用截断样本分析。
5. 当前缺陷编码精确匹配归 NG；`ng_type` 为空或 OK 且 `product_quality=1` 归 OK。其他缺陷和质量未知记录排除并计数，多缺陷字符串按完整编码拆分匹配，不用子串包含判断。
6. 配置ADS的工厂按目标记录中的真实租户、产线确定路线，读取字典内目标及上游工序对应的编码字段。相同字段直接关联，换码按ADS保留全部已确认上游码，再按目标租户查参数宽表。不混用两条路线、不按编码长度猜测；路线不明时记缺失并提示。未配置ADS的其他工厂仍沿用直接编码及唯一显式`product_in_code`关联，多投入码无法唯一确认时记缺失。
7. 每个上游工序一次选择全部已选特征列；按租户及 `(编码,目标分区时间)` 分批查询，默认每批2,000个请求，最多八条SQL同时执行，实际配置位于 `bi_app/.env` 的 `BI_NG_DEEP_QUERY_WORKERS=8`。先以批次最大目标时间为上界在数据库内按产品选取候选记录；候选在该产品自己的目标时间内时直接使用，候选晚于目标时间时，才对这些请求执行逐产品时点查询。这样不需要为所有请求都构造大型UNION关系，同时保持与逐产品时点查询完全相同的选择规则。SQL耗时按每条实际执行的查询分别记录。
8. 同一投入编码用于多个目标时间时，分别取对应时点的正确记录，不以全体产品的最大时间代替每个产品的时点。上游不复用目标的日期下界、班次、工单或设备条件，允许查询较早月份的真实生产记录。上游只匹配其分区时间不晚于目标记录分区时间的记录，没有有效分区时间则不关联。仅对连接丢失类只读查询重试一次，查询失败会取消尚未开始的批次。
9. 非共享工序箱线图统计使用全部有效有限数值，不填零、不抽样。箱体是25%–75%分位数，须是1.5×IQR内实际观测值。n是关联后的参数样本数，不是目标产品数；覆盖率按有至少一个有效参数的目标产品数计算，避免多码样本放大覆盖率。显示完全缺失与部分缺失，并单列追溯耗时；离群点参与统计但不绘制。气泡图保留全部有限参数用于等宽分箱，按区间内不同目标产品统计NG/OK。覆盖不足50%、分组为空或关联歧义时明确提示。默认200,000上限同时约束保留的追溯行和每个特征关联后的已知参数槽位，超限报错，不静默截断。

字段推荐是待验证的工艺假设；本阶段只完成取数和分布比较，不输出影响系数或已确认根因。

## 验证

### 证据报告排查顺序（2026-11-19）

前端的“4 证据报告”使用同一次分析保存的目标画像和模型结果，依次判断设备、班次、上游因素；历史结果也可直接使用该展示规则。设备异常优先展示设备证据、设备各班次表现和核查建议；未检出设备异常再判断班次；两层都未定位时，最多展示三个上游因素。设备/班次样本不足时明确保留“证据不足”，上游结果仅作为并行候选，不宣称前两层已排除。

明显偏高的默认判定：当前组和对照组各至少30个NG/OK产品、当前组至少5个NG、NG占比差至少0.10个百分点、至少为对照的3倍，并满足单侧Fisher精确检验经BH校正q≤0.05。设备仅与同租户、同产线的其他已知设备比较，未知设备/班次不作为正常对照。判定参数位于`frontend/src/features/agent-apps/ng-defect-analysis/rootReportData.ts`的`REPORT_RULES`。

上游因素按已完成模型输出的平均绝对SHAP排序，每个字段合并产品代表值中位数与多码极差的贡献；贡献占比以本轮全部有贡献记录的上游字段为分母，不在Top 3内部重新归一化。共享物料仍按目标产品构建模型，独立物料较少、字段覆盖不足、条件内关联反转等限制在对应候选中说明。不以常量或证据不足字段补齐三个因素。没有模型贡献结果时，只展示按分布差异排序的观察候选，不称为异常贡献排名。

设备/班次的占比偏高是优先核查方向，具体故障机制需结合设备记录及现场对照验证；SHAP贡献也不代表导致NG的因果比例。该报告调整不改变候选筛选、训练数据划分和现有取数/清洗规则。
