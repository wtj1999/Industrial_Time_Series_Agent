# 业务领域与智能体目录

设备域、生产域、市场域都先展示五个分类：通用智能体、金寨二期工厂智能体、金寨三期工厂智能体、芜湖一期工厂智能体、新站二期工厂智能体。

| 领域 | 通用智能体 | 金寨二期 | 金寨三期 | 芜湖一期 / 新站二期 |
| --- | --- | --- | --- | --- |
| 设备域 | 现有六个设备分析应用 | 空目录 | 空目录 | 空目录 |
| 生产域 | 电芯产量、PACK产量、工厂能耗预测 | 制造、品质、成本、设备 BI 分析 | 不良品类型分析 | 芜湖一期：四个 BI 分析；新站二期：空目录 |
| 市场域 | 现有七个预测应用 | 空目录 | 空目录 | 空目录 |

`domainConfig.ts` 集中维护领域元数据、应用展示注册表 `CATALOG_AGENTS` 及各领域成员分组；生产域成员继续由 `config.ts` 维护。设备域和市场域当前将全部已有应用放入通用分类，其余工厂为空。后续增加或调整成员，在 `getDomainGroups` 中维护对应领域的分组成员；新应用同时注册展示信息，并在 `MyAgentsView.tsx` 接入功能页。

`ProductionCatalog.tsx` 展示所有领域的分类、成员及空目录，`DomainCatalog` 展示一级领域。`CatalogCard.tsx` 是三个层级共用的卡片组件，统一圆角、边框、索引、标题、介绍、图标、入口箭头、悬停和键盘焦点样式。一级领域与具体应用共用不等宽高编排和领域配色（设备蓝、生产绿、市场暖橙）；分类目录沿用左侧大卡、右侧横纵卡及底部小卡的错落布局。尺寸是视觉布局，不代表应用数量。成员增多时自动延续网格；平板调整为双列，手机单列；尊重减少动态效果的系统偏好。

分类首页仅展示名称、通用介绍及「进入目录」，不展示具体应用名称、应用标签、智能体数量或当前是否为空。具体成员及空状态在进入分类后显示，扩充工厂应用无需修改首页文案。

`MyAgentsView.tsx` 保存当前领域、分类和应用。返回顺序为功能页 → 所属分类 → 领域分类目录 → 业务领域目录，桌面面包屑可直接返回上级。预测与设备分析应用沿用新建会话流程，BI 和 NG 问数沿用原有入口。

同步部署请同时更新本目录和 `components/views/MyAgentsView.tsx` 并重新构建前端，无新增依赖。已通过生产构建及模拟 API 的浏览器检查：21 个应用入口、15 个分类、逐级返回、所有空目录，以及 1440 / 768 / 390 像素视口的目录与成员列表无横向溢出。

三个领域通过 `catalog-theme-*` 的 CSS 变量管理各自色系，从一级卡片贯穿分类目录、应用卡片、空目录、装饰图形、焦点边框和页头图标；共享卡片结构与尺寸编排。

二级分类卡片的背景装饰由 `DirectoryArtwork.tsx` 按领域和卡片比例绘制：设备域为机械齿轮、仪表与监测信号；生产域为输送线、立体工序模块与流转路径；市场域为趋势图、全球网络与连接节点。五张卡片均有对应装饰，大卡、纵卡、横卡和小卡采用不同构图。全部沿用已有色系变量，无额外位图或依赖；SVG 仅用于装饰，不接收点击、不进入键盘焦点或无障碍阅读，标题及入口保持在前景。一级领域与具体应用卡片的装饰不受本次调整影响。

“我的数据”和“我的模型”通过 `components/ui/AssetCards.tsx` / `AssetCards.css` 复用 `CatalogCard` 的卡片结构与视觉样式，分类卡片固定等高 280px，详情列表使用等宽、等高网格，不使用领域目录的跨列跨行布局。装饰区分在线连接、离线文件、数据分析、异常检测、时序预测与数据表。在线数据源和数据表也沿用这一样式，原有预览、筛选、刷新及模型元数据流程保持原样。模型紫色为独立调色板，不改变现有三个领域的色系。部署时需同时同步新增的共享组件和样式，以及 `MyDataView.tsx`、`MyModelsView.tsx`、`OnlineDataView.tsx`。

侧栏 `components/layout/Sidebar.tsx` / `Sidebar.css` 复用相同配色变量、细线图标、同色边框、柔和渐变和圆角细节，保持 288px 宽的紧凑导航。资源入口分别使用数据蓝、模型紫、智能体绿，并以 `aria-current` 标记当前页面；会话、历史、示例和账户卡片沿用绿色基础色系。历史打开与删除使用独立按钮，键盘操作删除不会同时进入会话。侧栏滚动、窄屏隐藏、流式响应期间的禁用规则和现有路由保持原样。

生产域的芜湖一期目录已增加制造、品质、成本、设备四个 BI 入口，与金寨二期共用应用元数据及界面。`CatalogGroup.tenantId` 配置金寨二期 `11200001`、芜湖一期 `14100001`；进入 BI 时注入 `agent.tenantId`，页面所有查询和确认请求统一附加 `tenant_id`。工厂与应用共同作为页面 key，避免跨工厂保留旧会话。其他领域的同名工厂目录仍为空。
