# 平台公告维护

公告卡片位于登录后左侧栏“新建对话”下方，替代原“当前会话”卡片；Session 标识和对话轮次移至对话工作台上栏。手机端侧栏隐藏时，上栏铃铛提供同一公告面板入口。

右侧公告面板及背景遮罩在打开时用约0.36秒同步淡入，关闭时用约0.3秒淡出后再移除。关闭按钮、Esc、点击遮罩和内容跳转均走相同过渡；系统启用“减少动态效果”时直接开关。

侧栏卡片和右侧面板只展示最近7天的公告（北京时间今天及之前6个自然日，不展示未来时间），未读计数和所有分类也限定在这个范围。旧公告可保留在 JSON 中，超过时间自动不再展示。重新聚焦、刷新及每5分钟检查时更新日期窗口。

多条公告每10秒自动切换，使用约0.9秒的交叉淡入淡出，保留前后内容同时过渡，避免清空后重新显示造成闪烁。不显示进度条、页码、暂停/左右切换按钮及右上角时间范围文字；最近7天的筛选规则仍保留。鼠标悬停、键盘焦点进入、公告面板打开时自动暂停，后台标签页不轮播；系统开启“减少动态效果”时取消自动播放与过渡。轮播本身不标记已读，点击某条卡片后展开对应详情并记为已读。面板保留全部、未读、智能体上新、功能升级、平台通知分类。

## 日常发布

唯一内容文件是 `frontend/public/announcements.json`。无需修改 React 代码或数据库，不提供面向普通用户的编辑入口。部署人员直接维护该文件；不要在公告中放入数据库账号、密码或内部连接信息。

在 `items` 数组中添加一条：

```json
{
  "id": "20261120-new-agent",
  "publishedAt": "2026-11-20T09:00:00+08:00",
  "category": "agent",
  "title": "新增某某分析智能体",
  "summary": "简要说明新能力及适用场景。",
  "details": ["入口：我的智能体 → 生产域 → 所属工厂。", "说明主要能力和使用方式。"],
  "target": "/agents",
  "published": true
}
```

| 字段 | 规则 |
| --- | --- |
| id | 唯一且稳定，仅字母、数字、点、下划线、短横线，最长120字符；首次字符为字母或数字 |
| publishedAt | 完整日期时间，必须带时区，如 `2026-11-20T09:00:00+08:00`；面板按北京时间显示日期 |
| category | `agent` 智能体上新 / `feature` 功能升级 / `notice` 平台通知 |
| title / summary | 标题不超过120字符，摘要不超过600字符 |
| details | 文本数组，最多12条，每条最多1000字符；纯文本展示，不解析 HTML 或 Markdown |
| target | 可选，仅允许 `/agents`、`/datasets`、`/models`、`/chat`；跳转目录后由用户选择具体应用 |
| published | 可选，默认发布；设为 `false` 可保存草稿或撤下公告 |

日期晚于当前时间的条目暂不显示，到达时间后随下一次检查显示。数组最多500条，按发布日期倒序，同日期保持文件内顺序。最近7天公告进入侧栏轮播与面板。

## 校验与同步

发布前在项目目录运行：

```bash
npm run check:announcements --prefix frontend
```

当前 Docker Compose 将整个前端目录挂载到容器，日常公告更新只需将 JSON 文件同步到服务器 `/data/ts_agent/frontend/public/announcements.json`，不需要重建或重启容器。建议先校验，再通过临时文件原子替换正式文件，避免用户读到写入一半的 JSON。

前端在进入平台、窗口重新聚焦以及每5分钟检查时读取 JSON（`cache: no-store`）；公告面板也提供“刷新”。若使用 CDN/反向代理缓存，请对 `/announcements.json` 设置 `Cache-Control: no-cache` 或发布时清理该资源缓存。

若使用生产静态构建，首次部署需正常构建前端；以后只需把 JSON 同步到实际站点根目录的 `announcements.json`（通常 `frontend/dist/announcements.json`），仅修改源码 `public` 不会自动更新已有 `dist`。

格式错误或网络异常不会影响业务页面，已加载的公告会保留，面板提供错误提示和重试。部署新组件时需同步新增源码、JSON、package.json，构建/重启前端；后端无改动，无新增依赖。

## 已读与内容更正

展开公告才记为已读，打开面板本身不清空未读；也可手动“全部已读”。已读 ID 按登录账户保存在当前浏览器，跨标签页同步，但不跨设备同步；清理浏览器数据后会重新显示未读。

修正文案保留原 ID；如果是需要用户重新关注的重大更新，新增一条新 ID。撤下公告将 `published` 设为 `false` 或删除该条即可。

首批内容为近期功能集中收录，所填日期是公告发布日，不代表功能最初上线日期。后续发布时填写实际公告时间，并在正文注明功能上线时间（如果与公告日期不同）。
